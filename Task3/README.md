# Внешние интеграции

Добавляем домофон и шлагбаум в текущее приложение собственника. PropDevelopment проверяет права, партнёр распознаёт лицо или номер и управляет устройством.

- [Контекст C4](context.drawio), [SVG](context.svg).
- [Контейнеры C4](containers.drawio), [SVG](containers.svg).

На контейнерной схеме показан домен ЖКУ, где появляются новые сервисы. Остальные домены есть в [исходной схеме](../PropDevelopment_С4_model.drawio.xml).

## Что добавляем

Перед сервисами ЖКУ ставим API Gateway. `smart-access-service` хранит разрешения, согласия и состояния команд. CRM собственников подтверждает связь человека с квартирой. Для связи профилей используем `sub` из Keycloak и `person_id`, а не ФИО или телефон.

`partner-adapter` отвечает за обращения к партнёру. У партнёра нет прямого доступа к CRM и БД. Очередь используется для событий и изменений прав; команды открытия в неё не помещаем. Секреты храним в Secret Manager, действия записываем в журнал аудита.

## Требования

Сроки ниже предложены для этой интеграции и требуют согласования с партнёром.

| Область | Требование |
| --- | --- |
| Вход в приложение | OpenID Connect, OAuth 2.0 Authorization Code + PKCE S256 через системный браузер. Секрет клиента в приложении не хранится. Для администраторов нужна MFA, для выдачи доступа жильцам — повторное подтверждение личности. |
| Токены | Проверяем подпись, `iss`, `aud`, `exp` и scope. Access token действует не более 5 минут, refresh token хранится в защищённом хранилище ОС и ротируется. |
| Связь с партнёром | OAuth 2.0 Client Credentials и mTLS. Отдельные клиенты и scopes для каждой УК и среды. Пользовательский токен наружу не передаётся. |
| Права | Обе стороны проверяют пользователя, УК, дом и устройство при чтении и изменении. Подмена ID и служебных полей не даёт доступа к чужим объектам. Права чтения, открытия и изменения разрешений разделены. |
| Передача данных | HTTPS с TLS 1.2+, предпочтительно TLS 1.3; между сервисами — mTLS. Для видео — WebRTC с DTLS-SRTP и разрешение только на текущий вызов. Обычный видеозвонок не записывается. |
| Состав данных | Передаём идентификатор, разрешение и номер автомобиля при необходимости. ФИО, паспорт и платёжные реквизиты партнёру не нужны. Шаблоны лиц и видео обрабатываются у партнёра в РФ, в PropDevelopment и DWH не копируются. Зарегистрировать лицо можно только по одноразовому разрешению для конкретного человека. |
| Открытие | У команды есть ID и срок 10 секунд. Повтор с тем же ID не открывает устройство ещё раз; просроченную команду отвергает и само устройство. После таймаута проверяем статус той же команды. |
| События | Проверяем подпись JWS, отправителя, время и `event_id`. Подтверждаем событие после сохранения в очереди; повторная доставка не дублирует действие. Старое событие не возвращает отозванное право. |
| Отзыв и отказ связи | Отзыв доступа должен доходить до партнёра не более чем за 60 секунд. При потере связи распознавание не открывает вход. Остаются ключ, вызов диспетчера и безопасный выход. |
| Секреты и аудит | Ключи выдаются только адаптеру и ротируются. Записываем инициатора, объект, решение и результат команды. Токены, видео и полные номера в журнал не пишем. |

Для биометрии до запуска проверяем [152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/) и применимость [572-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_436110/), включая схему ЕБС/аккредитации партнёра. Нужно отдельное письменное согласие с возможностью отзыва. Отказ от биометрии не должен лишать человека обычного доступа в дом. Условия хранения и удаления закрепляем в договоре.

Протоколы: [RFC 9700](https://datatracker.ietf.org/doc/html/rfc9700), [RFC 8705](https://datatracker.ietf.org/doc/html/rfc8705).

## Взаимодействие

1. Собственник входит через Keycloak. Запрос из приложения проходит через Gateway и `tenant-core-app` в `smart-access-service`.
2. Сервис проверяет права на устройство и создаёт команду. Адаптер передаёт её партнёру с токеном нужной УК; партнёр повторно проверяет права.
3. Ответ `202` означает принятие команды. Открытие подтверждается событием устройства. Событие проходит через Gateway, адаптер и очередь, после чего приложение получает результат.
4. При распознавании лица или номера платформа партнёра проверяет актуальное разрешение. Вызов и кнопка открытия доступны без распознавания лица; шлагбаум использует ту же модель прав.

Перед подключением проверяем чужую УК, повтор команды, отзыв доступа и отказ партнёра. Изменения контракта согласуем с ИБ и командой ЖКУ.
